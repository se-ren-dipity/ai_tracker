# i讯飞文档整理约定

2026-10-29 更新。已确认：由用户定期发起“整合最近一周”任务；当前不建设独立文档 Agent、任务队列或每天自动写文档服务。早期持续维护方案已取消，不能作为待实施需求。

## 内容与模板

从本站已收集的模型、工程新闻和原文图片整理，保存成适合回看的文档。默认按用户指定的时间范围；“最近一周”写明实际起止日期。同一事件的重复报道归并，后续开源、API 开放与首次发布说明各自时间，不丢掉新增信息。

按文本模型、多模态、语音、图像、视频等分类，工程内容单独归类。每条沿用网页的阅读格式：标题、必要的背景与具体进展、参数和使用条件、相关图片。橘鸦已有总结可以直接保留；不额外添加来源说明、图例说明等章节。参数和许可证不确定时不编造，不将待确认档案当成已验证事实。

建议模板：

```text
AI 信息整理｜YYYY-MM-DD 至 YYYY-MM-DD

文本模型
  新闻标题
  正文段落
  相关图片

多模态模型 / 语音模型 / 图像模型 / 视频模型
  按同样格式整理，没有内容的分类省略

工程与工具
  具体进展、使用方式和必要图片
```

## 执行与边界

用户发起任务后，先读取已指定的 i讯飞文档和本站已有资料，核对已写内容，准备增量稿，再在授权文档中更新。保留用户的修改与笔记。写入后重新读取，确认文字和图片实际保存，避免重复追加。

文档接入取决于当次实际可用的连接器或浏览器。`xfchat.iflytek.com/docx/` 路径本身不能证明兼容飞书 API。登录或图片上传不可用时，保留待发布稿并说明需要协助的具体步骤；不能声称已上传。没有安排自动周任务，也没有部署服务器文档同步 worker。

可复用资料保留在本机 `data/document-drafts/`，不进入代码库或公开网页。文档整合与新闻每日北京时间 10 点采集相互独立，不阻塞模型入库。

## 状态与迭代

- 设计：按需周整理、按模态分类、保留图片与橘鸦总结，已确认。
- 实现：使用现有资料及当次文档编辑能力；无新增后台服务。
- 本机/服务器：本轮只校正文档，不执行外部写入；服务器无文档同步上线项。
- 2026-10-29：移除已被用户取消的每日文档队列、自动维护区域和多阶段 Agent 建设方案，统一为上述有效约定。
