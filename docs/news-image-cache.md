# 新闻图片服务器缓存

更新日期：2026-10-30。状态：本机实现与验证完成；服务器待部署验证。

## 要求与方案

已确认：新闻图片改为服务器下载缓存，浏览器通过本站加载；旧数据库不重采、不改写原始图片链接；保持现有网页、采集和模型三个服务。用户已授权推送 GitHub，并要求提供直接 Docker 更新命令。

首次请求图片时下载，成功后持久保存在数据库同目录的 `image-cache/`。首页、新闻详情、模型关联新闻使用新增 `cached_url`；收录原文接口仅在响应中把 img src 改为本站地址。原始 URL 保留用于追溯和服务端取图。首屏文字接口不等待图片下载；图片失败沿用已有封面候选回退和隐藏行为，不回退到浏览器直连图床。

接口为 `GET /api/articles/{article_id}/images/{sha256}`。请求必须对应数据库中该文章已收录的 img src，不接收任意 URL。只下载 HTTP/HTTPS、80/443 端口；禁止凭据、内网/回环/链路本地/保留地址。DNS 解析后连接固定的公网 IP，保留原 Host 和 TLS SNI/证书校验；逐跳检查重定向，最多 3 跳。不转发访客 Cookie/Authorization，不继承系统代理或 COLLECTOR_PROXY。

已实现默认值：单图最多 10 MiB，最多 4 个下载/缓存处理并发；同一 URL 的同时请求合并为一次下载。HTTP 单次网络等待 5 秒、传输循环总预算 30 秒（循环检查间仍可能有一次网络等待，系统 DNS 解析受操作系统超时控制）。图片路由确认文章归属后释放 SQLite 连接，再等待网络。仅接收文件头匹配的 PNG/JPEG/GIF/WebP/AVIF，拒绝 HTML、SVG 和压缩 HTTP 响应。成功缓存最多 512 MiB，写入前按文件修改时间清理最旧图片，写入采用临时文件原子替换；命中不刷新原图。不成功结果在进程内退避 60 秒，最多保留 256 条失败记录。浏览器缓存 1 天，响应启用 nosniff 和沙箱 CSP。

## 部署与限制

缓存写入既有 data 挂载，重建网页容器后保留；不进入 Git，也不嵌入镜像。不新增依赖和数据库表。本次只需重建网页容器，两个后台 worker 无需重启。源站失效、服务器出网失败或图床解析为内网地址时，首次下载仍会失败；已经缓存的图片继续可用。超限、SVG 等不支持图片按原页面回退逻辑处理。

服务器更新步骤记录在 [部署文档](deployment-ubuntu.md)。运行真源为 `backend/image_cache.py`，图片路由在 `backend/routers/articles.py`。安全边界参考 [OWASP SSRF 防护](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)，IP 固定连接使用 [HTTPX SNI 扩展](https://www.python-httpx.org/advanced/extensions/)。
