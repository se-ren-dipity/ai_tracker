# Windows 本地运行与每日采集

2026-10-29，v1.1。启动功能本地已验证，一键停止已通过本机隔离验证；服务器未验证。已确认要求：每天北京时间 10 点开始自动收集整理，并提供与启动脚本对应的一键停止入口。本地使用三个独立进程：网页 `web`、定时采集 `collector`、模型维护 `models`。打开网页或只启动 uvicorn 都不会启动另外两个进程。

## 统一启动

项目 `.venv` 已安装依赖时，在 PowerShell 运行：

```powershell
cd D:\模型收集
.\start-local.ps1
```

脚本只查找当前目录 `.venv` 启动的三个指定模块，补起缺失进程；重复执行复用现有进程，不手工另建采集任务。进程隐藏运行，日志写入 `data/logs/<角色>-<启动时间>.*.log`。本地网址固定 `http://127.0.0.1:8000/`，不会扩大监听到外网。约 40 秒内检查网页就绪和两个 worker 的数据库心跳，输出心跳换算为北京时间；任一不健康会报错，不能只凭网页打开就认定完整启动。

只读检查，不启动进程：

```powershell
.\start-local.ps1 -StatusOnly
```

进程匹配限定本项目 `.venv`；若另用全局 Python 手动运行，脚本不冒认其归属，应先核对原启动方式。文件锁仍负责阻止同一数据库的重复 worker。Windows 的 venv 可能同时显示一个 launcher 和一个实际 Python 子进程，这不等于两份采集任务。

该脚本是启动入口，不是 Windows 服务管理器：不注册开机任务、不自动重启崩溃进程，也不会阻止电脑休眠。机器重启后需要重新运行；要求长期无人值守时，使用现有 Linux Docker Compose 三服务部署，见[服务器手册](deployment-ubuntu.md)。不能把“当前在线”写成“重启后也必然在线”。

## 一键停止

双击项目根目录的 `stop-local.cmd`，或在 PowerShell 运行：

```powershell
.\stop-local.ps1
```

脚本按本项目 `.venv\Scripts\python.exe` 的实际可执行文件路径和三个服务模块定位进程，依次停止网页、采集和模型维护服务，使用 Windows `taskkill /T /F` 一并结束 venv 启动器及其子进程，并等待已识别的进程退出。不会按端口或 Python 名称批量结束其他应用。未运行的服务会提示 `not running`，可重复执行；双击入口执行后停留显示结果，失败返回非零退出码。通过脚本所在路径定位项目，从其他工作目录执行也适用。

仅预览停止对象可运行 `.\stop-local.ps1 -WhatIf`。默认直接停止，不等待当前采集或模型请求完成；已提交数据、日志和锁文件保留，系统释放进程持有的锁。下次运行 `start-local.ps1` 后，采集任务按现有中断恢复逻辑继续，模型任务等待原有租约到期后按重试规则处理；心跳记录可能在停止后最多 90 秒仍显示在线，不作为进程停止的验收依据。

适用范围为 `start-local.ps1` 启动的本机服务；全局 Python、其他虚拟环境手动启动或已经失去 venv 父进程的孤立进程，需要按原启动方式处理。无需安装新依赖、修改数据库或调整 Agent prompt；将两个停止脚本放在启动脚本同级即可。建议默认值为立即停止三个服务，无待确认事项；服务器继续使用 Docker Compose。

本机验收通过（Windows PowerShell 5.1）：在临时 venv 项目中确认三服务及多层子进程全部退出；其他项目的同名模块、本项目的相似模块名和仅在 `-c` 文本中提及目标模块的 Python 进程均保留；缺失服务及重复停止正常，`-WhatIf` 不结束进程。`stop-local.cmd` 已从其他目录调用验证，覆盖中文与空格路径，PowerShell 失败时返回非零退出码。正式服务仅运行预览并核对原进程仍在线，未为测试中断当前采集或网页；测试临时目录和进程已清理。

## 每天 10 点的含义

采集进程在线时，每 10 秒检查一次北京时间。10:00 以后为当天创建唯一的 `daily:YYYY-MM-DD` 任务，先 Models Table，再全部启用的新闻来源，然后联合分析新闻与模型、直接收录并对账、编排正文；模型进程默认只消费手动补查，自动周期复查关闭。见 [模型维护说明](model-agent-v1.md)。

10 点是开始时间，不承诺所有正文在 10:00:00 已发布。处理耗时取决于源站、文章量、模型调用与重试。10 点后恢复进程会自动补建当天缺失的任务；当天已经完成则不重复创建。不要清空数据库、删除锁文件或反复点“采集并更新”来修复离线进程。

检查入口为“管理员 → 运行管理”：先看 collector/models 是否在线，再看当天任务各阶段与重试情况。网页健康检查只证明 Web/API 和数据库可访问。
