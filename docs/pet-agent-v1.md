# 囤囤：第一版使用与验证

版本 0.7 · 2026-10-30。原 v0.6 已在 Linux 服务器运行；本轮基础待机 3 秒与静态资源版本更新已在本机实现，服务器待更新。

已接入用户提供的待机、检索、摸头三段可灵视频；透明转换与验证见[制作包与接入设计](pet-animation-production.md)。按用户要求先直接使用，接缝和表演细节后续优化。

已接入用户生成的六段待机：护宝、敲鼓、侧耳听、忍喷嚏、躲猫猫、打盹。基础待机 3 秒 → 完整随机小表演 → 基础待机，六段每轮打乱顺序、不重复，跨轮避免相同动作连播。

## 怎么使用

打开网站，仓鼠初始出现在右下角，点击“聊一聊”打开问答。可以查最近发布、按条件找模型、问工程进展或简单闲聊。回答带可点击引用和本站详情卡片；卡片跳转时收起面板。`↺` 清空本浏览器对话，`×` 收起，`−` 隐藏；隐藏后从页脚“AI 助手”唤回。Enter 发送，Shift+Enter 换行，Esc 收起。

采用用户提供的 `frontend/assets/pet/tuntun-cool.svg`，不改原图。待机在 3 秒 idle 与一段完整随机小表演之间交替；发送问题后从 thinking 开始循环 search，经过 searching、composing 时连续播放，不重新起播；完成反馈 1.2 秒后回视觉待机，失败、待补充保留对应 SVG 动作，取消回到待机。双击/摸头菜单播放一次 pat。加载中、失败或不支持透明视频时回退 SVG。网页后台、隐藏或离屏暂停视频并清除随机特演，减少动态效果设置停止视频和 CSS 动画。桌面和手机尺寸适配现有明暗主题；没有语音、上传文件或桌面常驻。

### 搬位置和互动

- 按住角色拖动，或拖聊天标题栏，角色和已展开面板会整体移动；靠近边缘自动限制在可见范围。松手后不误开聊天。
- 位置只保存在当前浏览器的 `tracker.pet.position`，按可用空间的比例记录；刷新恢复，窗口缩小重新约束，不写服务器。
- 双击角色或快速轻点两下，播放约 10 秒摸头回应，结束回到当前状态；再次双击可重播。建议默认判定为同类指针在 400ms 内、相距不超过 24px 的两次点击。单击不启动或打断动画，拖动超过 6px 才中断当前互动；拖拽、取消、长按菜单和失焦会清除连点记录。真实问答处理中保留 search。右键、触屏长按 500ms 或 `···` 打开动作面板，菜单“摸摸头”仍单次点击触发。
- 键盘聚焦角色后，Enter/空格一次即可摸头；方向键微调，Shift + 方向键加速，Home 复位；Esc 退出菜单或收起对话。
- 互动不会调用大模型或扣问答额度，也不会把正在搜索的任务标为完成。没有随机漫游和甩抛物理；用户放在哪里，就在那里陪伴。

互动位于 `frontend/pet-interaction.js`，视频层位于 `frontend/pet-video.js`，`pet.js` 负责问答。更新部署需同时发布 HTML、三份 JS、CSS、原 SVG 和 `frontend/assets/pet/animations/` 九段 v2 WebM；静态资源版本号已更新，无数据库迁移或后端配置变更。素材转换只在开发机运行。

管理员进入“运行管理 → 囤囤 · 访客助手”，可以开关助手与联网，调整八项额度，并查看今日轮次、LLM 调用、输入/输出 token、联网次数及进行中数量。保存接口使用原管理员登录和 CSRF，访客接口不提供任何管理权限。

## 实际运行逻辑

1. 浏览器独立匿名会话 → 同源/CSRF、速率和额度校验 → 原子预留一次问答。
2. 单个只读 Agent 调用现有数据库查询与受限官方联网。访客不访问待审核模型和管理健康详情，不触发采集、审核、入库或文件/命令执行。
3. 新闻按来源报道日检索，在已整理 Insight 层去重。模型按总参数、上下文、类型及权重开放状态筛选，明确符合和字段未知分组。
4. 工具返回过长时节选并标注；上下文拥挤时提前整理。最终 Answer 校验结构、真实证据 ID、已展示候选 ID 和链接来源。未读链接不能作证据，首次失败最多修正一次，仍失败则显示已找到的卡片和未完成原因。
5. SSE 返回阶段与最终结果，不流出草稿。断线后的后台请求继续到完成或超时，重新打开只恢复原请求，不重复付费。点击停止会取消；清空递增会话版本，旧结果不能写回。

固定提示词的唯一正文是 [system_prompt.txt](../backend/assistant/system_prompt.txt)；后端注入北京时间、精确日期范围和 schema。默认沿用 `DEEPSEEK_API_KEY`、`deepseek-chat`，本机供应商响应标识为 `deepseek-flash`。可用环境变量 `ASSISTANT_MODEL` 单独指定模型。无需部署 MCP 给网页使用；外部可信客户端的原 MCP 新增 `search_news` 与 `find_models`，与助手复用查询代码。

## 默认额度与数据

| 范围 | 默认上限 |
| --- | --- |
| 浏览器会话 | 每日 20 次、每分钟 3 次、同时 1 个请求 |
| IP / 全站 | 每日 100 / 200 次，全站同时 3 个请求 |
| 单轮 | 最多 4 次 LLM、8 次工具、2 次搜索 + 2 次正文读取、90 秒 |
| 输入 / 输出 | 问题 2,000 字符；每次输出 2,000 token；历史最多 6 轮且合计不超过 2,200 字符 |
| 全站每日 LLM | 600 次调用、200 万输入 token、20 万输出 token |

按北京时间重置，计量存 SQLite，重启不清零。每次 LLM 调用先预留 12K 输入/2K 输出 token，再按供应商 usage 结算；无 usage 时保留预留。上下文以 24KB UTF-8 近似控制，并非精确 tokenizer；实际使用超出估计时计量如实增加，后续调用停止。已付费的失败或取消仍计额度，未开始任何付费调用的失败释放每日轮次。全站联网最多为每日轮次上限的四倍，且单轮仍限制为四次。

浏览器凭证为 HttpOnly + SameSite=Strict Cookie。默认 HTTPS Secure Cookie，沿用 `ADMIN_COOKIE_SECURE`，本地 HTTP 使用 false。会话 token 在数据库只存摘要。首次会话建立限制每 IP 每分钟 15 次；消息还有独立 IP 速率限制，不信任任意转发头。

新增四张表：`assistant_sessions`、`assistant_requests`、`assistant_usage`、`assistant_config`。清空立即移除正文并保留计量；24 小时后禁止读取，启动和每小时清理过期正文，计量记录保留 8 天。备份也可能含对话与管理会话，应保持私有。聊天文本不放 localStorage，只存隐藏偏好。

## 部署与回退

没有新增依赖。首次升级前运行 `python -m backend.backup`。本次本机迁移前备份：`data/backups/tracker-20261028-152506.db`。启动自动创建四张表，原有模型和新闻结构不变。

当前 ARM64 服务器按[部署说明](deployment-ubuntu.md)运行 `bash scripts/update-server-web.sh`，只重建网页容器；本轮不迁移数据库或改动后台任务。原 Compose 部署仍可用以下流程：

```bash
docker compose exec -T backend python -m backend.backup
docker compose build
docker compose up -d
docker compose logs --tail=100 backend
```

问答在 Web 进程内异步执行，**同一个数据库只能运行一个 Web 进程**，进程锁会拒绝重复启动；不要设置 `uvicorn --workers 2` 或复制 backend 容器。采集和模型维护 worker 继续独立运行。进程崩溃后重启将未完成问答标为 interrupted，不自动再次调用模型。需要多 Web 进程时再引入共享执行队列，第一版不增加 Redis/Celery。

反向代理的 `/api/assistant/` 要保留 Host 和协议信息，配置可信代理地址，关闭 SSE 缓冲（`proxy_buffering off`），`proxy_read_timeout` 建议 120s。不能向公网开放任意可信 `X-Forwarded-For`，也不能用多实例规避锁。

关闭助手可在管理页保存开关，后续模型/联网调用将停止；已发出的请求可能完成。代码回退恢复旧版本即可忽略新表，不要为了回退助手删除当前模型与新闻数据。需要恢复整个数据库时，按原部署说明先停服务并保留新数据副本。

## 随机待机（v0.7 当前行为）

- 用户将动作间隔改为 3 秒：依据 idle 视频实际播放进度达到 3 秒切换，不再等待约 10 秒的整段循环。每段表演仍保留完整约 10 秒，结束重新开始 3 秒基础待机；下载缓冲可能延长实际等待。
- 提问立即切 search、空闲时双击切 pat；实际拖拽暂停媒体，松手按当前请求状态恢复。单击不打断。done 的完成反馈 1.2 秒后回视觉待机，真实请求状态和回答保持不变；error/waiting 不被随机动作覆盖。
- 隐藏、离屏、后台、减少动态效果时不安排特演；恢复从基础待机重新开始，工作状态按当前请求恢复。坏片本页跳过；仅按需加载，不一次下载全部九段，不调用模型、不扣额度。
- 发布九段 v2 共 4,932,008 字节，统一取景以容纳毛束变化。原视频与原三段 v1 发布文件保留。2,169 帧透明边缘与无音轨验证通过，26 项宠物前端测试通过；没有修改问答后端与 prompt，不重复付费评测。
- Edge 本机检查：六段新增视频都实际解码并启用透明播放；自动队列由 idle 切入 peek/idle_listen，思考切 search、摸头切 pat，完成反馈后保持 done 状态并回 idle。深底 120px、白底 78px 显示通过；正式页面已刷新并加载三份新版 JS 与 v2 视频。隐藏/离屏后丢弃特演、拖拽阻断、减少动效与跨轮不重复由自动测试覆盖。Chrome、Safari、真实移动设备及服务器未验证。

## 仍需明确的限制

引用校验保证来源和候选可追溯，不能逐句证明模型推理正确。原始档案中的缺失、旧值与冲突仍会影响推荐；目前缺少足够可比的长文评测，不应理解为自动生成权威能力榜。关键词召回和节选可能遗漏事件，开放权重与开源代码也可能需要进一步核对。第一版适合作为带出处的查询助手。

官方补查使用有限域名列表，尚未涵盖所有厂商；GitHub/Hugging Face/论文站点的发布者身份仍需结合资料判断。访客额度识别浏览器会话和 IP，不等于可靠的自然人限额。

旧版本 Linux Docker 构建和静态媒体显示已验证；本轮 3 秒间隔尚待服务器更新。代理下 SSE 断线/超时、实际手机键盘和多访客压力测试尚未执行。
