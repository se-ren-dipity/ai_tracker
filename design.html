需求定义（第一性原理）

📰 情报流

每天 5 分钟扫一眼业界动态，不错过重要进展。

关键要求：内容密度高、每条读完即懂、关键信息视觉突出。

🗂 模型选型

选型时快速找到"哪个模型适合这个场景"。

关键要求：字段准确、多维过滤、持续跟随最新发布更新。

整体架构

橘鸦 RSS / AIHOT RSS + 详情页 │ 每天北京时间 09:00；启动时也执行；每轮最多 30 份新原文 ▼ articles 原文档案（清理后的 HTML + 全文文本，URL 去重） │ 橘鸦按新闻章节拆条，AIHOT 单篇作为一条 ▼ source_items（独立条目、原文章节、链接、处理状态与原因） │ 每批 6 条完整信息 + 用户关注范围 + 候选已有事件 ▼ DeepSeek 情报 Agent ├─ 分类：模型发布 / 工程进展 / 行业动态 ├─ 事实 + 原文摘录 / 影响分析 / 待验证点 / 后续关注 ├─ 同一事件合并并保留来源；不同版本或不同事件分开 └─ JSON、条目 ID、引用定位及合并目标校验 │ 校验失败保留 failed 状态，待下一次整理重试 ▼ insights 情报库 ← SourceItem.insight_id 追溯全部出处 └─ 编辑 Agent → 连贯正文 + 对应章节配图 + 文末延伸阅读 ├─ 首页：焦点文章与图文列表，日期、分类、搜索、分页 ├─ 详情：连贯正文与关键配图，文末提供延伸阅读和出处 ├─ 页脚内容管理：更新状态、模型审核、原文档案 └─ 新模型名称 / Models Table / 新报道 / 到期复查 → model_tasks 持久任务 → 独立执行进程：联网研究 → 保存研究结果 → 判断入库 → 模型档案与关联报道

信源策略

目前收录橘鸦与 AIHOT。两者提供候选资料，项目 Agent 再整理、分析并合并同一事件。单次采集上限 30 份原文，每天 09:00 与服务启动时触发；手动整理只处理数据库里的待处理及失败条目。
信源RSS 地址每日条数处理方式
橘鸦早报 daily.juya.uk/rss.xml 10-20 条 原文归档，新闻章节拆分后逐条分析
AIHOT 模型 aihot.news/feed/full/category/ai-models.xml 5-15 条 单篇归档并分析，同一事件关联多个出处
AIHOT 行业 aihot.news/feed/full/category/industry.xml 3-8 条 单篇归档并分析，同一事件关联多个出处

DeepSeek API 职责

输入独立信息的完整正文、当前关注范围与可能重复的已有事件。行业信息与模型、工程同样保留，不因融资、商业或产品类别直接降权。

任务输出质量约束
整理独立事件标题、摘要、分类、关键词、优先级每条输入有对应状态；过滤保留原因
事实提取关键事实、原文摘录、来源条目 ID逐条校验摘录能在原文定位；不代表事实已核实
分析影响影响分析、限制与待验证点、后续关注分析与信源陈述分开，不假装访问过一手链接
同事件合并事件标识、已有事件关联、多来源重复报道保留出处；不同版本、榜单变化和第三方上架分别处理
Model card benchmark 抽取数值 JSON低置信度、待人工核实

结构化输出校验失败会重试一次；仍失败则保存 failed 状态，不发布无依据的情报。页面可重试。鉴权、余额或限流错误停止剩余批次。去重和分析由模型判断，仍可能误合并或漏合并。

模型资料 Agent

触发条件

新闻识别出新模型、LifeArchitect 公开表导入候选，或在模型审核页运行资料 Agent。可批量处理草稿、补查已有模型，也可单独处理一条记录。

执行流程

1
汇集候选：新闻中的 model_names[] 或公开表提供名称和初始资料。已有模型从库中读取当前字段。
2
并行查询（asyncio.gather）
① GET huggingface.co/api/models/{id} → 参数量、license、pipeline_tag、语言、下载量 （仓库匹配仍需确认）
② GET huggingface.co/{id}/raw/main/README.md → DeepSeek 抽取 benchmark （低置信，需审核）
③ 如找不到精确 HF ID，先用 HF search API 搜索最相关的
3
整合草稿，每字段标置信度 
{
  "name": "Qwen3-30B",
  "type": "LLM",           // pipeline_tag 映射 → 高
  "params_b": 30.0,        // safetensors.total / tags → 高
  "license": "Apache 2.0", // cardData.license → 高
  "context_length": null,  // 难以可靠提取，留空待确认
  "benchmarks": {...},     // README 提取 → 低，需核实
  "hf_url": "...",
  "hf_downloads": 12345,
  "confidence": {
    "type": "high", "params_b": "high",
    "license": "high", "benchmarks": "low"
  }
}
4
联网补查：现有 DeepSeek Key 调用 Search / Fetch，Agent 自主选择关键词、跟进官网、模型卡、报告和提供商文档。每个模型最多搜索 3 次、读取 4 个页面；研究结束先保存结果，再判断入库。空字段自动补充，月份日期可细化；与现值不同的资料形成更正建议，在管理页处理。
5
判断并入库：有可信资料证明具体模型存在即可收录。闭源、参数未公开、无 HF 仓库、暂未开放使用都不阻止入库；官方公布的研究模型也收录。身份仍不确定才暂缓，明确不是模型的标为未收录。按名称去重，已有模型原位补充，失败保留已有数据。

“模型库 → 模型审核”提供排队、复查、任务状态和资料更正入口。独立执行进程使用 90 秒租约、每 20 秒续期，进程退出后可接续已保存的研究结果；每项最多尝试 3 次，之后由管理页重试。一般模型每 7 天复查，闭源或明确有未公开字段的模型每 30 天复查，新报道可提前触发。运行与审核信息只在管理页展示。

模型名称进入独立档案：简介、能力规格、相关报道、资料入口及已采用的更新。字段区分已知、尚未找到、明确未公开、不适用和冲突。模型存在状态与权重、API、公布日、开放日分别保存。一篇文章可以关联多个模型。

API 端点

端点说明
GET /api/insights整理后的情报：day/category/q/page/page_size
GET /api/insights/{id}正文段落、章节配图、延伸链接；保留底层事实与出处
GET /api/insights/dates已发布文章的可浏览日期，首页不加载后台状态
GET /api/insights/status数量、处理状态、日期和关注范围
POST /api/insights/refresh整理待处理/失败条目，进程内避免重复运行
GET /api/articles文章列表，支持 q / category / source / page 过滤
GET /api/articles/{id}读取已入库正文，站内阅读；列表接口不携带完整正文
GET /api/articles/today今日文章，按类别分组
GET /api/articles/daily/{date}指定日期日报
GET /api/articles/sources信源列表及条数
GET /api/models模型列表，支持 type / org / license / params / ctx / lang / q / sort
GET /api/models/filters过滤器可选值（类型/机构/许可证）
GET /api/models/{id}模型档案、相关文章、已采用更新及资料入口
POST /api/models手工新增模型条目
GET /api/pending按 status 查看待确认、已入库、未收录及全部记录
POST /api/pending/review后台运行资料 Agent；pending_id 可指定一条记录
POST /api/pending/enrich补查缺少资料的已入库模型；model_id 可指定模型
GET /api/pending/changes待处理的字段更正建议
POST /api/pending/changes/{id}/accept 或 dismiss采用更正或保留现值，保留历史依据
POST /api/pending/{id}/approve审核通过 → 入库
POST /api/pending/{id}/reject丢弃草稿

运行与恢复

分析费用由条目正文、候选事件和输出长度决定，以 API 账单为准。完整分析比旧版关键词分类消耗更多 token；成功条目不会重复分析。

python -m backend.collector.backfill_content   # 旧摘要补采正文
python -m backend.collector.process_insights   # 拆分、分析待处理/失败信息
python -m unittest discover -s backend/tests -v

SQLite 自动增量迁移，原文章节与已有模型保留。改造前备份为 data/tracker.before-insights.db。使用单个服务进程；离线整理命令不要与服务内整理并发运行。无 HF 资料时草稿保留未知字段，不猜类型或输入输出模态。
